# Current architecture after Stage 6

React/TypeScript remains the client. Express and Socket.IO run in one process. Development mounts Vite; production hosts only dist/client. Private compiled server/account/database tools live under dist/server.

Persistence is Node's built-in SQLite, checked at runtime (minimum SQLite3.51.3; verified3.53.3). The connection uses WAL, synchronous FULL, foreign_keys ON and a busy timeout. schema.ts records migration version/application ID. Unsupported or corrupt existing databases fail rather than reset.

The original59 collection families and five extension families have separate indexed tables. File versions, time entries and feedback now have real services; jobs/jobHistory reserve later automation storage. Tables keep indexed identity/scope/date/amount fields plus complete JSON payloads to preserve old fields/order. Entity and relation registries enforce valid links with SQL foreign keys, including conversation replies, read cursors and fixed asset versions. Versioned reference upgrades allow only previously persisted anomalies; new duplicate/orphan input fails. Unknown root properties and settings are retained. Old anomalies retain raw source/quarantine copies with bounded allowances. Existing Prisma/PostgreSQL schema is a historical unused design artifact; SQLite schema.ts is authoritative.

DbService exposes stable compatibility state and begin/commit/rollback. PersistenceCoordinator serializes units, snapshots state, commits SQLite before res.end and defers business events until commit. Writes compare payloads, indexes and relations and update changed rows only. Failure restores the stable root and suppresses unpublished events. Failed authentication preserves only explicitly marked security audit independently. Socket read receipts use mutateResult and acknowledge after commit. Streamed assets register rollback cleanup and explicitly commit/release the authorized unit before emitting download bytes. Background work must use explicit units rather than changing shared state outside this boundary.

Scoped policy authenticates every private route, resolves live workspace membership, validates resource parents and department actions, rejects protected request fields and masks responses. System administration does not grant business access to unrelated workspaces. Auth, workspaces, system, project/task and organization modules own their services. server/files owns actual bytes and immutable versions; server/portal owns exact expiring public capabilities and feedback; server/chat owns conversation membership, messages, requests, reactions, pins and receipts; server/notifications owns personal inbox state and permission-filtered activity. server.ts wires these boundaries and retains later-stage integration routes.

Socket.IO verifies the session and workspace at handshake, action, delivery and periodic expiry checks. Room names and claimed user IDs never grant membership. Conversation authorization is shared with HTTP/file reads, including current team grants and ordinary-group connection constraints. Business events carry invalidations so recipients refetch their own projections. Presence is derived from valid live sockets and never rewrites account status. The client clears sockets/caches on identity changes, reauthenticates and rejoins on reconnect, and rejects responses from former identities/conversations. Voice and previews use authenticated fixed-version blobs with bounded temporary URL lifetimes.

A sibling PID lock prevents server/maintenance races and remains outside atomic restore directory swaps. Local password recovery updates hash, retained revoked session records and canonical JWT key in one transaction; the external key file is only a compatibility mirror. Logout, password/identity changes, account deactivation and session termination revoke both HTTP and live socket authority.

JSON migration analyzes every collection, preserves IDs/fields, reports conflicts and uncertain dates, imports in one transaction into a temporary database, verifies integrity and publishes without overwriting. Active JSON is never written in parallel. Database maintenance provides dry-run/import/status/export, stopped-server consistent VACUUM INTO backup with asset hashes, validated restore with preserved prior directory, and interrupted-restore recovery marker/gate. Missing browser-local data or lost blobs are not fabricated.

The compatibility model still reads and validates all collections in memory and supports one local server process; this is not a completed multiprocess SQL repository rewrite. Remaining stages cover scheduled jobs, real optional integrations, remaining sample analytics and final UX/performance work. The large client chunk still needs loading optimization. Local execution does not require Docker, PostgreSQL, Redis or an external API.
